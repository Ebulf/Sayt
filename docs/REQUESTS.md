# Заявки

Посетитель открывает тариф, нажимает «Оставить заявку», заполняет имя, телефон, регион и удобный способ связи. Название, оператор и абонентская плата определяются сервером по ID тарифа. Клиент не может подменить их полями формы.

`requests.js` отвечает за форму и состояния, `assets/request-config.js` содержит только публичный адрес отправки. `backend/requests.gs` — исходник Google Apps Script. `node scripts/build-request-backend.cjs` создаёт `reports/request-backend.gs`, добавляя 64 предложения из `assets/content.js`. После изменения каталога нужно обновить код и версию Google-развёртывания вместе с сайтом.

Google Script Properties содержат `SPREADSHEET_ID`, `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Их нет в клиентском коде и репозитории. Таблица доступна только владельцу. Telegram получает номер заявки, название тарифа и ссылку; имя, телефон и комментарий остаются в таблице. Бот: `@EbulfTarifyRequestsBot`.

Сначала сервер сохраняет строку, затем отправляет уведомление. Если Telegram недоступен, строка сохраняется со статусом уведомления «Ожидает». Триггер повторяет попытку каждые пять минут. Номер заявки и статус клиента находятся в разных столбцах: клиентские статусы — «Новая», «Связались», «Оформляем», «Подключён», «Отказ».

Повторная отправка с тем же ID возвращает тот же номер. Блокировка защищает одновременные записи; контакты и согласие проверяются сервером; строки защищены от исполнения формул. Есть скрытая ловушка для простых ботов, пауза 60 секунд между заявками одного телефона и ограничение 100 новых заявок в час. Эти ограничения используют кеш Google; это базовая защита, не полноценная CAPTCHA. При заметном спаме следует добавить отдельную проверку.

Форма показывает успех только после ответа сервера. При сбое сохраняет черновик и ID для повтора. Черновик хранится только до перезагрузки. Можно закрыть и снова открыть описание без потери данных; подтверждение не теряется. Сайт не принимает оплату и не подключает тариф сам: менеджер проверяет условия и связывается с клиентом.
